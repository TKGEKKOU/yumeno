# YUMENO Web / Desktop 最小验收矩阵

> 版本基线：`main` @ `c1b4ae7`（2026-09-02）
>
> 目的：用最少的人工步骤确认 Web 与 Desktop 共用的对话、文件、Agent、RVC 与服务生命周期没有明显回归。

## 1. 执行前提

- Python 3.11 与项目 `.venv` 已准备；
- 已配置至少一个可用的 LLM Provider；
- RVC 验收额外需要 FFmpeg、分离模型、`.pth` 与可选 `.index`；
- 使用新建会话，避免旧 checkpoint 或旧任务污染；
- 测试文件准备：一个短 MP3/MP4（建议 10–30 秒）和一个较长音频（可选）。

## 2. 最小矩阵

| ID | 场景 | Web | Desktop | 通过标准 |
|---|---|---:|---:|---|
| W1 | 启动与首页 | ✓ | ✓ | 服务启动，无 Python 异常，页面可打开 |
| W2 | 普通对话 | ✓ | ✓ | 用户消息发送后输入框清空，并收到回复 |
| W3 | 文件附件 | ✓ | ✓ | 上传后显示文件名、类型、大小和状态；刷新后仍可见 |
| W4 | RVC 意图入口 | ✓ | ✓ | 先经过 Agent/Worker 交接，再出现 RVC 工作区，不因关键词直接弹卡片 |
| W5 | RVC 文件处理 | ✓ | ✓ | 上传源文件 → 确认处理 → 进度 → vocals/instrumental；失败显示真实原因 |
| W6 | RVC 结果生成 | ✓ | ✓ | 选择音轨、模型与参数后生成最终音频并可播放/下载 |
| W7 | 中止与恢复 | ✓ | ✓ | 中止后轮询停止，随后普通对话可立即发送 |
| W8 | RAG/文档入口 | ✓ | ✓ | 文档可上传并进入统一附件链路；未配置依赖时显示明确不可用状态 |
| W9 | 设置与资源状态 | ✓ | ✓ | 对话偏好即时生效；完整设置/Provider 页面可打开 |
| W10 | Desktop 生命周期 | — | ✓ | 关闭 Desktop 宿主后 FastAPI/ASR 按设计停止；外部 Docker 按设计保留 |

## 3. 推荐执行顺序

### Web

```powershell
.\scripts\start.ps1 -NoInstall
```

浏览器访问 `http://127.0.0.1:17000/static/index.html`，依次执行 W2、W3、W4、W5、W6、W7。

### Desktop

先停止 Web 服务，再执行：

```powershell
.\.venv\Scripts\python.exe -B desktop_main.py
```

使用 Desktop 启动器打开的工作台，重复执行 W2、W3、W4、W5、W6、W7，并额外执行 W10。

## 5. 判定规则

- **通过**：页面行为符合通过标准，无未处理异常；
- **条件通过**：功能代码链路正常，但可选本地模型、FFmpeg、Provider 或外部服务未配置；
- **失败**：出现卡死、状态误报、消息无法继续、任务无法中止、文件引用丢失或前端未捕获异常；
- W5/W6 任一失败时，不将 RVC 标记为端到端通过。

## 6. 当前边界

这是一份最小人工验收矩阵，不替代全量自动化测试，也不把“代码测试通过”当成真实本地模型端到端成功。测试时应记录具体阶段、session/task ID、后端日志和浏览器控制台错误。
