# GPT-SoVITS 单引擎 TTS 设计

## 目标

YUMENO 的文字转语音功能统一使用 GPT-SoVITS。移除 Lunar/Qwen3-TTS 的产品代码、运行库、第三方源码、配置、界面和测试，同时保护 GPT-SoVITS 的安装、训练、推理、音色数据和补丁目录。

同一个 GPT-SoVITS 音色应能稳定朗读中文、日语及其他受支持语言。参考音频语言和待合成文本语言必须独立建模，训练流程必须阻止乱码或语言标签错误的数据进入训练。

## 架构

应用只初始化一个 GPT-SoVITS 适配器。预览、人物消息合成、HTTP 分段流式合成和 WebSocket 增量合成都调用同一个合成服务，不再存在 Lunar worker、Lunar 资源管理器或双引擎选择。

GPT-SoVITS 的服务启动继续按需执行，并可在应用启动后后台预热。应用关闭时停止其子进程。全局 TTS 状态直接反映 GPT-SoVITS 的安装、运行和错误状态。

## 语言模型

音色资产保存 `reference_language`，表示参考音频和参考转写的真实语言。允许值与当前 GPT-SoVITS v2Pro 能力一致：`zh`、`ja`、`en`、`ko`、`yue`。已有资产从训练 `.list` 的语言列迁移；不能可靠确定时标记为需要确认，不静默假定中文。

合成请求保存或计算独立的 `text_language`：

- 明确指定时使用用户选择。
- 自动模式按文本片段检测语言。
- 含平假名或片假名的片段优先判定为日语。
- 仅含拉丁字符的片段按英文处理。
- 纯汉字短句存在中日歧义时，使用人物的默认输出语言；未配置默认语言时，API 返回“语言不确定”，前端要求用户选择，不静默按中文处理。
- 混合语言文本按句子和文字系统边界分段，各段使用正确的 `text_lang` 合成，最后合并 WAV。

每次 GPT-SoVITS 请求必须满足：

- `prompt_lang = voice_asset.reference_language`
- `text_lang = 当前文本片段语言`
- `prompt_text = 参考音频对应的正确转写`

人物配置可保存默认输出语言或 `auto`，但不能覆盖音色资产的参考语言。

## 训练与数据校验

Voice Studio 创建训练任务时必须选择素材语言。ASR 请求应携带该语言提示，返回文本以 Unicode 字符串处理，并以 UTF-8 写入 `.list`。

训练启动前执行以下校验：

- 每个片段都有非空转写。
- `.list` 的语言标签属于允许集合，并与任务素材语言一致。
- 日语数据包含合理比例的日文字符；中文数据不得主要由日文假名组成。
- 拒绝包含典型错误转码序列的文本，例如大量 `銇`、`銈`、`仭` 等字符组合。
- 随机展示或记录若干标注样本，便于在昂贵训练开始前确认。

校验失败时训练任务进入明确的失败状态，保留数据用于修正，不生成或发布音色权重。

## 旧资产迁移

迁移过程只更新元数据，不删除用户的 `data/gpt_sovits/` 文件。

- 正常 `.list` 且语言一致的音色自动写入 `reference_language`。
- 乱码、空转写或标签明显错误的音色标记为 `needs_retraining`，不得绑定到新合成流程。
- 已绑定的问题音色在人物编辑和合成请求中显示可操作错误，提示重新标注并训练。
- 不尝试仅靠修改语言标签修复已经使用错误音素训练出的权重。

## API 与界面

保留现有 `/api/tts` 产品入口，但其实现全部委托 GPT-SoVITS。删除 engine 切换字段和 Lunar 安装、模型变体、GPU 开关等 Lunar 专属控制。

设置页只显示 GPT-SoVITS 安装目录、服务状态、启动/停止、日志与安装管理。人物编辑页提供默认输出语言：自动、中文、日语、英文等。音色管理页显示参考语言和资产有效性。

普通合成、HTTP 流式合成和 WebSocket 合成使用相同的音色校验、语言解析和错误映射，避免接口不同导致引擎或行为不同。

## 清理边界

明确删除 Lunar 专属内容：

- `voice/tts/`
- `runtime/tts/`
- `third_party/lunar_tts/`
- Lunar 资源配置、安装 API、前端设置和对应测试
- 对 `LocalTTS`、`TTSResourceManager`、Lunar/Qwen3-TTS 可执行文件及模型路径的引用

明确保护 GPT-SoVITS 内容：

- `voice/gpt_sovits/`
- `runtime/gpt_sovits/`
- `runtime/gpt_sovits_patches/`
- `data/gpt_sovits/`
- GPT-SoVITS 安装、训练、音色、推理及回归测试

清理必须使用明确路径和引用清单，不使用 `*tts*`、`*sovits*` 等模糊删除规则。

## 错误处理

未安装 GPT-SoVITS、服务启动失败、人物未绑定音色、音色需要重训、语言不确定和训练标注无效分别返回可区分的错误。流式接口发送结构化错误事件且不持久化不完整音频；普通接口不留下失败输出文件。

## 验收与测试

- 所有 TTS 入口只调用 GPT-SoVITS，仓库不存在 Lunar 运行时引用。
- `何の用かしら` 使用日语音色时发送 `prompt_lang=ja`、`text_lang=ja`。
- 同一日语音色朗读中文时发送 `prompt_lang=ja`、`text_lang=zh`。
- 中日混合文本按语言分段并按顺序合并。
- 典型乱码日文和错误 `ZH` 标签在训练前被拒绝。
- 普通、HTTP 流式和 WebSocket 合成共享相同路由语义。
- 迁移不删除 `data/gpt_sovits/`，问题音色被标记为需要重训。
- GPT-SoVITS 安装、启动、训练和合成测试通过；Lunar 专属测试和资源已移除。
- 静态页面不再展示 Lunar、Qwen3-TTS 或双引擎选择。
