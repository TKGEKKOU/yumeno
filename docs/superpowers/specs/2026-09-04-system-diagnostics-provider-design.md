# 系统诊断与供应商配置统一设计

日期：2026-09-04

## 目标

重新设计系统工作台的运行状态与服务供应商页面：运行状态面向只读诊断和监控，供应商页面面向外部服务配置；二者边界清晰、跳转准确、视觉统一，并消除进入供应商页面时的固定闪烁。

## 范围与约束

- 保持 Core Agent、Supervisor、Worker、Native Runtime、Job、Session、启动方式和用户数据边界不变。
- 数据库信息只读，不提供删除、清空、重建索引等高风险操作。
- 允许增加或整理最小只读聚合数据接口。
- 不把 GPT-SoVITS、RVC、Milvus Lite、SQLite 冒充成外部供应商配置。

## 系统总览

### 系统结论

根据真实检查结果显示：正常、部分能力待命、需要配置、存在异常、检查中，并显示检查时间及是否影响核心对话链路。

### 核心链路

展示 Web 服务、Agent Runtime、Session/Job、SQLite、LLM 的状态、职责、影响和准确操作入口。

### 按需能力

单独展示 GPT-SoVITS、ASR、RVC、Live2D、Milvus Lite、FFmpeg、Embedding、Reranker 等按需服务，区分已安装可启动、未启动（正常待命）、启动中、已启动、启动失败和未安装。

### 数据库与存储诊断

SQLite 只读展示类型、路径、存在性、大小、最后修改时间、连接状态、WAL/Journal、表数量、角色/会话/消息/任务/附件/文档统计、最近写入和迁移状态。

Milvus Lite 只读展示启用状态、数据库路径、大小、连接状态、Collection 数量、向量数量、Embedding 配置、最近索引/检索时间、错误和健康检索结果。

存储摘要展示数据、附件、任务结果、知识库、用户模型和受管运行资源目录及磁盘容量，不提供危险清理操作。

## 精确跳转

- LLM、Embedding、Reranker、联网搜索、远程 TTS/ASR → 系统/服务供应商对应服务区域。
- GPT-SoVITS、ASR → 声音/GPT-SoVITS 服务。
- RVC → 声音/RVC。
- 知识库、Milvus → 知识/总览。
- SQLite → 仅保留系统总览诊断，不跳转外部管理页。

## 服务供应商页面

去除大标题、上下说明小字和重复描述。保留顶部标签与宽配置卡片，复用工作台背景、间距、状态和操作规范。

各服务按自身语义配置字段：LLM、联网搜索、Embedding、Reranker、远程 TTS/ASR 分别使用不同字段，不强行统一为模型/来源/设备。每张卡片有明确启用开关、状态、主要保存或测试操作及错误反馈。

## 闪烁修复

检查页面切换生命周期、初始化调用、Vue 与静态页面重复挂载、is-hidden/is-active 时序和异步状态整体替换。采用稳定骨架与局部更新，避免空壳/旧内容/新内容连续替换造成闪烁；重复进入页面不得重复注册事件或发起不必要请求。

## 验收

- 数据库信息真实、详细且只读。
- 所有前往配置入口定位准确。
- 供应商页面无大标题和上下说明文字，视觉与其它工作台统一。
- 进入、刷新、快速切换供应商页无固定闪烁和重复挂载。
- 现有功能、启动方式、用户资源和后端架构不受影响。
- Python、前端测试、类型检查、构建、语法检查、编译检查、git diff --check 和真实 Web 冒烟测试通过。
