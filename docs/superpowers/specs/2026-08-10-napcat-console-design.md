# NapCat 连接控制台设计

## 目标

在 YUMENO 侧边栏“接入”下方新增独立的“NapCat”页面，为外部独立运行的 NapCatQQ 提供轻量 OneBot 11 连接控制台。YUMENO 不安装、启动、停止或更新 NapCatQQ。

## 范围

页面提供：

- OneBot 11 接入启用开关。
- 反向 WebSocket 地址展示与复制。
- Access Token 配置状态、更新和显式清除。
- 默认角色选择。
- 群聊触发方式（@角色或指令前缀）及前缀设置。
- 连接状态、客户端数量、连接时间、最近事件时间和最近错误。
- NapCatQQ Desktop 的最小配置参考。
- 手动重新检查状态。

本次不提供：

- NapCatQQ 的安装、进程托管、版本更新或登录控制。
- 完整联系人管理、消息历史浏览或调试聊天窗口。
- 图片、文件消息段和复杂转发消息。
- QQ 官方机器人配置或能力。

## 信息架构

侧边栏顺序为：

1. 接入
2. NapCat
3. 扩展

“接入”页面继续承载 B 站直播控制台；“NapCat”页面只承载真实 QQ 用户号经 OneBot 11 接入的设置和运行状态。

页面采用操作型控制台布局，包含四个无嵌套区域：

1. 顶部状态栏：启用状态、连接状态、客户端数量、最近事件。
2. 连接地址：当前页面来源推导的反向 WebSocket URL与复制按钮。
3. 接入配置：启用、Token、默认角色、群聊触发方式和前缀。
4. 连接检查与 NapCat 填写参考：逐项反馈 YUMENO、OneBot 和 NapCat 状态。
5. 发信台：选择私聊/群聊目标，发送文字、语音或文字加语音。

NapCat 参考值固定为：

- 类型：`WS 反向客户端`。
- 消息上报格式：`Array`。
- 连接角色：`Universal（全双工，API + 事件）`。
- 心跳间隔：`30000 ms`。
- 重连间隔：`5000 ms`。
- URL：`ws://<YUMENO主机>:17000/api/onebot/ws`（HTTPS 页面使用 `wss://`）。
- NapCat 的鉴权 Token 必须与 YUMENO 保存的 OneBot Token 完全一致。
- “上报 Bot 自身发出的消息”默认关闭，避免回复回流形成重复事件；需要调试时由用户手动开启。
- “开启调试输出”默认关闭。

## 发信台

发信台只在 OneBot 客户端已连接时启用。目标列表通过 OneBot API 请求获取并按私聊/群聊分组；没有目标或 API 不支持时保留手动填写 ID 的降级入口。

- 文本发送调用 `send_private_msg` 或 `send_group_msg`。
- 语音发送使用 `record` 消息段，语音文件由 YUMENO 的现有 TTS 生成器产生。
- “文字 + 语音”先发送文字，语音生成成功后再发送语音；语音失败不撤回文字，并在发送记录中显示原因。
- 自动回复和手动发送共用发送锁，保证同一目标的消息顺序；不同目标可以并行。
- 自动回复默认发送文字和语音，两个开关都可单独关闭。
- 自动回复按收到事件的会话目标回复，不使用手动选择的目标。
- 每条发送结果进入本地页面内存记录，保留最近 50 条，不写入聊天记忆。

## 状态模型

- `disabled`：OneBot 接入未启用。
- `waiting`：接入已启用，但没有 NapCat 客户端连接。
- `connected`：至少有一个 NapCat 客户端连接。
- `error`：最近出现连接或协议错误，且当前没有可用客户端。

前端每 2 秒请求现有集成状态接口。页面隐藏或切换后停止轮询，重新进入页面时立即刷新，避免无意义后台请求。

后端 OneBot 状态新增：

- `connected_at`：首个当前连接建立时间。
- `last_event_at`：最近收到 OneBot 上报的时间。
- `last_error_at`：最近错误时间。
- `error`：精简后的最近错误。

状态时间使用 UTC ISO 8601 字符串，由前端按本地时间显示。

## 配置与安全

- Access Token 不通过任何读取接口回显。
- Token 输入留空表示保留已有 Token，避免页面保存时意外清除。
- 页面提供独立“清除 Token”动作，并要求用户确认。
- 反向 WebSocket 地址默认使用当前网页主机与端口，协议随 HTTP/HTTPS 切换为 WS/WSS。
- 页面说明 Token 留空只适合本机测试；跨设备或公网连接必须配置 Token。
- YUMENO 继续接受 `Authorization: Bearer <token>` 或查询参数 `access_token`，兼容 NapCat 配置能力。

## 后端接口

复用：

- `GET /api/integrations`
- `PUT /api/integrations/onebot11`
- `WS /api/onebot/ws`

新增：

- `DELETE /api/integrations/onebot11/token`：显式清除保存的 Token，并立即刷新运行时配置。

配置更新保持现有语义：普通 `PUT` 请求中的空 Token 不覆盖旧值。

## 错误与反馈

- 保存成功后显示短暂、明确的成功反馈，并立即刷新状态。
- 保存失败保留用户尚未提交的表单值。
- 复制失败时提示用户手动复制，不静默失败。
- NapCat 断开时状态从“已连接”回到“等待连接”，不显示为 YUMENO 故障。
- OneBot 被禁用时，页面不把“没有连接”显示成异常。
- Token 不匹配导致的 WebSocket 拒绝应记录为最近错误，但不能记录 Token 内容。
- 用户若曾把 Token 截图或粘贴到外部渠道，应立即在 NapCat 与 YUMENO 两端同时更换；文档、日志和页面均不得展示 Token 明文。

## 测试

- API：配置保存、空 Token 保留、显式清除、Token 永不回显。
- WebSocket：未启用拒绝、鉴权失败拒绝、成功连接、断开、事件时间更新。
- 现有私聊与群聊文本收发测试保持通过。
- 前端：状态派生、URL 生成、导航注册、轮询生命周期和表单条件显示。
- 手动浏览器检查：桌面与窄窗口布局、复制反馈、保存反馈、页面切换。

## 验收标准

- 侧边栏“接入”下方可进入独立 NapCat 页面。
- 用户无需阅读项目文档即可在页面中得到 NapCat 反向 WebSocket 的准确填写值。
- NapCat 连接后 2 秒内显示“已连接”和正确客户端数量。
- NapCat 断开后 2 秒内显示“等待连接”。
- Token 在任何读取响应和页面初始化数据中都不出现明文。
- 新页面不影响对话页、Live2D 页面和 B 站接入页的生命周期。
