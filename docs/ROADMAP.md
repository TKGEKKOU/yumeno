# YUMENO 最终形态与方向

## 一句话方向

YUMENO 的最终形态是一个 **Web-first 的本地优先角色工作台**：用户在一个浏览器入口创建、训练、编排、观察和部署私有 Agent；角色拥有稳定的人设、记忆、知识、声音和形象，平台用确定性的 Workflow、评测和审计保证结果可控。

核心判断：**桌面壳只是分发方式，Web 才是主工作面。** 后端继续保留本地优先与隐私优势，但产品入口、数据模型、API、实时通道、配置中心和可观测性都按 Web 应用优先演进。

## 产品终局

### 1. 角色即运行时

角色不只是“聊天档案”，而是一个可部署的运行单元：

- 人设、声音、Live2D、知识库、记忆、工具权限、模型偏好、渠道入口组成同一份角色运行时。
- 每个角色有明确的版本号、发布状态、变更 diff 和回滚能力。
- 角色可以发布到本地 Web 工作台、桌面壳、B 站、OneBot/NapCat、语音通话或未来的 API Endpoint。

### 2. Web 控制台是唯一权威入口

Web 控制台承担五类任务：

1. **对话**：流式回复、语音、Live2D、HITL 确认、会话管理。
2. **创作**：角色草稿、资料导入、知识空间、音色训练、形象绑定。
3. **编排**：Supervisor、Worker、工具、Skill、MCP、权限与确认策略。
4. **知识**：上传、解析、切分、向量化、检索质量、结构化查询。
5. **观测**：运行状态、成本、延迟、RAG trace、失败原因、审计日志。

### 3. 可审计的 Agent/RAG 引擎

平台的差异化不是“又一个角色”，而是“每一步可解释”：

- 检索、改写、纠错、拒答、工具调用、外发动作都有 trace。
- 评测集可以反复跑，形成质量基线。
- 管理类动作默认 HITL，高风险外发默认确认。
- 本地数据不出本机，云端模型按角色显式授权。

## 架构形态

### 前端

前端从“多页脚本 + 静态 HTML”演进为 **模块化 Web 工作台**：

- Shell 负责路由、导航、状态中心、通知与权限。
- 对话、角色、知识、能力、评测、设置是六个一级域。
- 表单、状态卡、进度条、确认框、空态、错误态统一组件。
- Vue 用于复杂工作台；轻量页面可继续使用原生 JS，但共享同一 API client、状态模型与设计 token。

### 后端

FastAPI 仍然是本地编排核心：

- `app/` 负责 API 和装配。
- `agents/` 负责策略、Workflow、工具和权限。
- `rag/` 负责检索、质量门、纠错与评测。
- `voice/`、`live/`、`integrations/` 是能力适配层。
- `data/` 存放本地状态；Milvus 负责向量检索；SQLite 负责应用与 checkpoint。

### 安全模型

Web-first 不等于公开服务。安全边界固定为三层：

1. **本地默认**：服务绑定 `127.0.0.1`，管理 API 校验本机来源。
2. **显式暴露**：若未来提供远程访问，必须启用认证、HTTPS、CORS 白名单、CSRF 防护、速率限制与审计。
3. **角色权限**：工具、知识空间、记忆和外部渠道按角色授权，客户端永远不能扩大作用域。

## 阶段路线

### Phase 1：Web 基础稳定

目标：把 Web 工作台变成可靠默认入口。

- 统一 API client：超时、错误格式、`X-YUMENO-Request`、重试和本地请求校验。
- 统一确认弹窗、错误提示、加载态和空态。
- 设置页按“模型与联网 / 知识与检索 / 语音引擎”分组。
- 清理废弃页面、备份文件和旧桌面优先代码。
- 验收：所有关键页面无控制台错误，接口失败都有清晰反馈。

### Phase 2：角色运行时发布

目标：角色从草稿变成可版本化资产。

- 引入角色版本、发布、回滚和 diff。
- 工具、Skill、MCP、知识空间和音色绑定进入同一份角色配置。
- 支持“测试角色”和“发布角色”两条链路。
- 验收：修改角色配置可审查、可确认、可回滚。

### Phase 3：知识与评测闭环

目标：让 RAG 质量变成日常操作。

- 文档导入后自动生成处理报告。
- 每个知识空间维护评测集。
- 查询结果保存检索 trace 和用户反馈。
- 评测报告能指向具体文档、切分策略或 reranker 配置。
- 当前增量：查询摘要/证据/公开 trace/反馈已持久化；按角色的质量报告和评测历史已可查询；文档处理元数据已进入报告数据结构；知识空间已支持人工评测题集 CRUD。
- 评测运行模式：`generated` 使用自动生成题集，`manual` 只运行启用的人工题，`combined` 按“人工题 + 自动题”运行；人工题关联的 DocumentJob 会在可用时解析为 Milvus chunk 标注，无法解析时退回免标注自动相关性判定。
- 已完成增量：失败样本可从低置信度、未接地和负反馈查询同步到待确认候选池；候选必须经人工确认后才会写入正式人工题集，也可直接忽略，避免未经审核的答案污染回归基线。
- 验收：质量下降能定位到“数据、检索、生成或权限”。

### Phase 4：多渠道统一运行

目标：所有入口复用同一角色运行时。

- B 站、OneBot/NapCat、语音、Live2D 共享同一套会话、记忆与权限。
- 渠道只负责协议转换，不复制业务逻辑。
- 所有外发动作进入统一确认与频控。
- 验收：同一角色在不同入口表现一致。

### Phase 5：远程与协作

目标：在保持本地优先的前提下安全扩展。

- 可选账号系统和远程工作区。
- 团队角色库、权限审核和部署模板。
- 浏览器端实时协作或共享评测报告。
- 验收：远程模式默认关闭，开启后有完整安全边界。

## 不做什么

- 不把 YUMENO 改成纯 SaaS 云托管聊天产品。
- 不为了多平台牺牲本地数据和可审计性。
- 不让每个渠道维护独立 Agent 逻辑。
- 不在缺少认证和安全设计时默认开放远程访问。

## 北极星指标

- **首次可用时间**：新用户从启动到完成第一次角色对话的时间。
- **知识可信率**：回答有证据、可溯源、低幻觉的比例。
- **管理动作安全率**：高风险操作全部经过确认、权限和审计。
- **恢复能力**：模型、Milvus、语音或渠道故障时 UI 可解释且主功能可降级。
